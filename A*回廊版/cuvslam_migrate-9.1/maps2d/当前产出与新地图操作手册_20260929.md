## 4. “标定”需要确认什么

这里把参数标定/核验和人工标注分开。现有工具有手工高度切片，**没有自动地面拟合、一键地面标定或相机内外参标定功能**。

### 4.1 坐标方向和实际尺度

工具沿用保存地图的原始坐标：二维水平面取 XZ，Y 作为高度方向。不要为了让图看起来朝上而单独旋转标注或参考点。

在现场找两处可明确对应的地面位置，测量真实间距，再用地图 XZ 坐标计算：

```text
d_map = sqrt((X2-X1)^2 + (Z2-Z1)^2)
```

在回廊不同位置、不同方向重复核验。若尺度明显不一致或有漂移，应查源地图、深度尺度和建图状态；`--resolution 0.05` 只控制栅格大小，不会修正错误的地图尺度。

### 4.2 地面高度 Y

高度切片使用公式：

```text
相对地面高度 h = ground_y - 点的原始 Y
```

操作步骤：

1. 先导出 `source_map.json`，暂时不要填写 `--ground-y 0` 来猜地面。
2. 通过原始 3D 点云和现场位置确认几组真正属于地面的点，分布在入口、直道和转角，读取其原地图 Y。Rerun 的 `map_xyz/features` 显示原始 XYZ，也可以核对源 JSON 中对应点的 `pose.y`。现有二维标注窗口只投影 XZ，不能从二维点击位置直接得出地面 Y。
3. 如果这些地面点的 Y 大致一致，可用已确认地面点的代表值（例如中位数）作为 `ground_y` 的初值。不能用所有特征点的 Y 中位数代替地面识别；天花板、墙面和离群点会混入。
4. 在标注器填写“地面 Y”“高度下限”“高度上限”，点 Apply。先用相对高度 `[-0.15,+0.15]m` 观察，再根据已确认地面点的噪声调整。
5. 检查整圈黄线附近的地面特征是否都能合理显示；只在一小段看起来正确，不代表整个地图已标定。记录参考点、地面 Y、切片范围和核验日期。

例如，**仅当实测确认该地图 ground_y=0.70m**，相对高度 `[-0.15,+0.15]m` 才对应原始 Y 范围 `[0.55,0.85]m`。0.70 是示例，不是当前地图已确认的数值。

地面 Y 是地图坐标，不随当前相机移动而变化，也不一定等于相机安装高度。若地面点 Y 随位置明显变化，可能存在地面坡度、坐标轴倾斜或地图误差；单个固定 Y 薄层不足以处理。当前工具不做地面平面拟合或自动坐标变换，应先核验坐标/地面条件，不能通过盲目加宽切片宣称标定完成。

**显示切片与候选障碍是两套独立参数：**

| 参数 | 影响 |
|---|---|
| 标注器 `--display-ground-y`、`--display-height-min/max` | 灰色底图和红点的显示切片；不改变生成器的障碍策略 |
| 标注器 `--ground-y`、`--height-min/max` | 哪些点显示为候选红点；不给 ground-y 就不产生候选集合 |
| 生成器 `--ground-y`、`--height-min/max` | 哪些原始点投影为真正参与合成的候选障碍格 |
| 标注器 `--hide-candidates` / Red | 只隐藏红色着色；不删除点或改变地图包 |

因此 `--height-min 0.5 --height-max 5` 不是灰色底图筛选条件；也不是“自动找到黄色线”。源点没有 RGB。当前采用的流程是显示切片辅助找地面纹理，再人工沿禁越黄线标墙，生成地图时不启用未经核验的自动高度候选。

显示切片参数不会保存进 `annotations.json`，再次启动需重新输入或写入启动命令。建议每张图单独保存一份 `calibration_notes.md`，记录地面 Y、切片范围、尺度实测、包络半径、安全余量及源数据库身份；这份记录需要人工填写，工具不会自动生成测量结论。

### 4.3 机器人包络与余量

生成器使用圆形包络。半径应覆盖所选机器人参考点到最远外缘的水平距离，包括突出部件；不能总是只取车宽的一半。若参考点恰在矩形车体中心，覆盖整个矩形的半径为 `sqrt((车长/2)^2+(车宽/2)^2)`；参考点有偏置时按实际外缘距离核验。

`--robot-radius-m` 是包络半径，`--safety-margin-m` 是额外余量。当前 0.50m、0m 是已用配置，换机器人或安装方式后需重新核验。工具并未建立相机到机器人包络中心的在线定位转换，这部分属于后续集成。

Free 标注实际确认可走的空间，WallSeg 沿真实禁越线画；尺寸和余量由生成器扣除，不要在画墙时又把墙整体向内平移一遍。

## 5. 人工标注怎么做

| 类型/操作 | 用途与方式 |
|---|---|
| Free / 1 | 已确认可走的地面范围；点矩形两个对角点完成；边与地图 X/Z 轴平行 |
| WallSeg / 5 | 沿黄线等禁越边界点两个端点画一段虚拟墙；折线按多段绘制 |
| Obstacle / 2 | 有面积的固定障碍、墙体等；左键加顶点，右键闭合 |
| Unknown / 3 | 未核验、规划不应进入的区域；多边形操作同上 |
| RemoveCand / 4 | 剔除误判的自动候选障碍；不删除人工障碍，不直接声明自由 |
| Erase / 6 | 擦除干扰特征点，半径 0.05–3m 可调；只记录点 ID |
| Select / 7 → Delete | 选中青色高亮项后删除，适用于自由区、障碍区和墙线等 |
| Ctrl+Z / Ctrl+Y | 撤销/重做完整绘制、删除、擦除；历史限当前窗口内最近 100 次操作 |
| z / Backspace | 撤销未完成多边形末点，或取消矩形/墙线的第一个点 |
| Save / w | 保存完成的标注；q 保存退出，关闭窗口也保存完成项 |

建议先找到地面边界，标出自由空间，再沿禁越黄线画墙，并补充实体障碍。没有点、隐藏点、擦掉点都不等于自由空间；**自由区需要标**。

现场连续可走的相邻自由矩形要有实质重叠，不能只靠肉眼看似贴边。本次两处修复各向已有自由区内重叠约 0.15m；新图应根据实际空间核验，不能越过真实隔断搭桥。标注自由区的边缘格采用保守规则，再扣除机器人包络，细缝会切断通路。

擦除不移动坐标，不改变米制尺度，也不修改 `data.mdb`。它会影响哪些点参与重新生成，进而可能改变包围范围和栅格原点；重新生成后必须使用新 `map.json`，不可复用旧行列编号。开高度切片时只擦当前高度层，隐藏高度点保留。删除虚拟墙用 Select/Delete，擦特征点不会删除已画墙线。

合成优先级为：人工障碍/墙线 ＞ 人工未知 ＞ 未剔除的候选障碍 ＞ 人工自由 ＞ 默认未知。Free 不能盖掉墙或障碍。

## 6. 换一张地图，从零开始

以下以 `viz_test_03` 为新地图名称示例。先准备完成建图且停止写入的 `orbbec/viz_test_03/data.mdb`；本流程从已有保存地图开始，不负责采集建图。不同数据库即使位于同一现场，也不能默认共享坐标或地面 Y。

### 第一步：设置本次路径和实测参数

```bash
cd /home/amov/cuvslam_migrate-9.1
TASK_MAP_ID=viz_test_03
TASK_MAP_DIR="$PWD/orbbec/$TASK_MAP_ID"
TASK_OUTPUT="$PWD/maps2d/$TASK_MAP_ID"
TASK_EXTRACTOR=/home/amov/cuVSLAM-main1/cuVSLAM-main/build_jetson/bin/map_extractor
TASK_RESOLUTION=0.05
TASK_RADIUS=0.50
TASK_MARGIN=0.00
```

修改地图名称及路径；这里半径和余量只是沿用当前地图的演示值，实际执行前按第 4 节核验。后续命令在同一个终端运行；新开终端需重新设置这些变量。

本机需使用 `build_jetson/bin/map_extractor` 的 aarch64 版本。`run_map2d_builder.sh` 会使用工程 venv 并配置所需动态库，不要替换为另一个架构的旧导出器。

### 第二步：导出初始草稿和原始点云

```bash
./run_map2d_builder.sh \
  --map-dir "$TASK_MAP_DIR" --map-id "$TASK_MAP_ID" \
  --extractor "$TASK_EXTRACTOR" \
  --output "$TASK_OUTPUT/v1_source_draft" \
  --resolution "$TASK_RESOLUTION" \
  --robot-radius-m "$TASK_RADIUS" --safety-margin-m "$TASK_MARGIN"
```

不传旧标注、不猜 ground-y、不加 review。得到 `source_map.json`、`map.json`、`grid.npz`、空标注和预览。此时没有自由区，地图全未知、可通行格为 0 是正常状态；这一版用于开始标注。

### 第三步：核验地面、开始标注

先不启用高度筛选打开：

```bash
./run_map2d_annotator.sh \
  --source-json "$TASK_OUTPUT/v1_source_draft/source_map.json" \
  --hide-candidates \
  --out "$TASK_OUTPUT/annotations_working.json"
```

按第 4、5 节完成地面核验、显示切片和人工标注。保存后，再运行同一命令会自动恢复 `annotations_working.json`。新图必须使用自己的输出路径；不要加载旧地图的坐标、墙线或擦除 ID。

如果已确认该新图地面 Y，可把显示参数写进命令。例如下列 **0.70 仅为已确认数值的写法示例**：

```bash
./run_map2d_annotator.sh \
  --source-json "$TASK_OUTPUT/v1_source_draft/source_map.json" \
  --display-ground-y 0.70 \
  --display-height-min -0.15 --display-height-max 0.15 \
  --hide-candidates \
  --out "$TASK_OUTPUT/annotations_working.json"
```

### 第四步：把完成的标注生成规划草稿

```bash
./run_map2d_builder.sh \
  --map-dir "$TASK_MAP_DIR" --map-id "$TASK_MAP_ID" \
  --extractor "$TASK_EXTRACTOR" \
  --output "$TASK_OUTPUT/v2_annotated_draft" \
  --resolution "$TASK_RESOLUTION" \
  --robot-radius-m "$TASK_RADIUS" --safety-margin-m "$TASK_MARGIN" \
  --annotations "$TASK_OUTPUT/annotations_working.json"
```

这里继续采用人工标注，不传生成器 ground-y。显示切片不需要带到生成器。如果以后决定启用自动候选，需用核验后的地面 Y 和机器人碰撞高度带，并在草稿、审核生成时保持完全相同的参数；不能直接套用旧 `0.5–5m`。

### 第五步：查看预览，验证回廊是否连通

先查看 `v2_annotated_draft/preview.png`，检查墙线、自由区、转角和窄通道。编写该地图自己的 `$TASK_OUTPUT/probes.json`，记录若干确认位于通道内部的 XZ 坐标及需要连通的点对。可参考现有 [probes.json 的格式](viz_test_02/audit_20260929_060638/probes.json)，但不要照搬旧图坐标。

格式如下，**0、1 只展示格式，必须换成新图实际坐标后使用**：

```json
{
  "points": [
    {"id": "A", "xz": [0.0, 0.0]},
    {"id": "B", "xz": [1.0, 1.0]}
  ],
  "pairs": [["A", "B"]]
}
```

运行验收：

```bash
venv/bin/python orbbec/validate_map2d.py \
  --map "$TASK_OUTPUT/v2_annotated_draft" \
  --probes "$TASK_OUTPUT/probes.json" \
  --output "$TASK_OUTPUT/audit_v2"
```

输出 `validation.png`、`validation.json`；成功退出码为 0，检查或路径失败时为 2。重点看 `checks`、`all_probe_paths_pass`、端点状态及 `connected_components`。完整回廊应按现场意图连通；不同房间确有隔断时，不能为追求 1 个连通块而错误补自由区。

若现场可走但图不通，检查自由区之间的细缝、墙线误画、候选障碍以及包络参数。修正 `annotations_working.json` 后输出**另一个版本目录**重新验证，不覆盖已发布地图。

### 第六步：人工确认后发布审核版

确认地图与现场一致、参数合理、所需路径通过，保持草稿的源地图、标注和生成参数不变，再生成：

```bash
./run_map2d_builder.sh \
  --map-dir "$TASK_MAP_DIR" --map-id "$TASK_MAP_ID" \
  --extractor "$TASK_EXTRACTOR" \
  --output "$TASK_OUTPUT/v3_reviewed" \
  --resolution "$TASK_RESOLUTION" \
  --robot-radius-m "$TASK_RADIUS" --safety-margin-m "$TASK_MARGIN" \
  --annotations "$TASK_OUTPUT/annotations_working.json" \
  --review
```

`--review` 是人工确认后的标记，不会自动判断现场。选点规划器会拒绝 `reviewed=false`。如果草稿之后修改了标注或生成参数，需先验证新结果，再审核。

可对发布包再运行一次第 5 步验证，把 `--map` 换成 `v3_reviewed`、输出换成 `audit_v3`，确认发布包结果。

### 第七步：在新地图上使用 A*

```bash
./run_map2d_astar.sh \
  --map "$TASK_OUTPUT/v3_reviewed" \
  --output "$TASK_OUTPUT/astar_routes"
```

必须同时注意这两个路径：`--map` 指定新图；`--output` 指定新图结果目录。若都省略，程序仍默认使用 `viz_test_02/v6_reviewed`，不会根据最近编辑的地图自动切换。

无窗口模式同样指定新图，`--start`、`--goal` 后填写新图的二维米制坐标。此模式下 `--output` 是尚不存在的**具体结果目录**，不是 GUI 模式中的父目录。

## 7. 在当前 v6 基础上继续修改

无需重做原始标注。首次从 v6 导入到一个新的工作文件：

```bash
cd /home/amov/cuvslam_migrate-9.1
./run_map2d_annotator.sh \
  --source-json maps2d/viz_test_02/v6_reviewed/source_map.json \
  --annotations maps2d/viz_test_02/v6_reviewed/annotations.json \
  --hide-candidates \
  --out maps2d/viz_test_02/annotations_next.json
```

这个首次导入命令只在 `annotations_next.json` 还未开始工作时使用。后续继续编辑应去掉 `--annotations`，让工具自动读取已保存的新工作文件：

```bash
./run_map2d_annotator.sh \
  --source-json maps2d/viz_test_02/v6_reviewed/source_map.json \
  --hide-candidates \
  --out maps2d/viz_test_02/annotations_next.json
```

原因：显式 `--annotations` 的加载优先级高于 `--out`。每次都指定 v6 输入会重新载入旧快照，保存时可能覆盖工作文件的后续修改。

保存完成后，按照第 6 节生成 `v7_annotated_draft` 等新版本，验证后再发布新的审核版。编辑器 Save 只更新标注 JSON，**不会自动重建 `grid.npz`，也不会更新已打开 A* 的地图**。

## 9. 常见问题定位

| 现象 | 首先检查 |
|---|---|
| 没有红点 | 没给候选 ground-y、Red 关闭、显示切片排除了候选，或擦除/候选范围影响；不代表地图没有障碍 |
| 开切片后全空 | 地面 Y、符号和上下限；空白不等于自由区 |
| 没有深绿色 | 是否画了 Free；通道能否容纳包络；是否被墙/未知/自动候选覆盖 |
| 转角看着相连却无路 | 两块 Free 的细缝、墙端点位置、保守边界栅格与包络扣除 |
| 修改标注后规划没变化 | 是否重新生成新地图包，并让 A* 的 `--map` 指向它、重启加载 |
| 换图后还看到原回廊 | 是否遗漏 `--map`；是否加载了旧 annotations 或 source |
| 输出目录非空 | 换新版本/新结果目录；已审核包不能用 force 覆盖 |
| 未审核地图无法规划 | 先对草稿做现场核验和离线验收，再以同样参数生成 review 版本 |
| 起终点被拒绝 | 点在未知、障碍、浅绿或贴边处；选深绿色内部，程序不会跨墙自动吸附 |
| 15 点不足以表达路线 | 路线转折太多；工具拒绝为凑点数删掉必要转角，应调整任务分段 |
| 地图超过 5000 万格 | 核验源点离群、标注范围和地图质量；生成器会停止，不能把失败草稿当地图使用 |
